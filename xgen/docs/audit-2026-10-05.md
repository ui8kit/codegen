# Audit of xgen, 2026-10-05

Scope: the generation layer (`xgen/*`), the specs, the fixtures, the dictionary, the generated packages and the 26 generated apps.
Every class of problem found has a rule in `xgen check`, so it cannot come back unnoticed. The check has 18 groups; this audit added `structure`, `hardcode`, `dead`, `duplicates`, `versions`, `tests`, `registry`, `themes`.

Headroom: the build is linear in the number of specs, there is no cache and none is needed. At 3x (about 180 blocks, 1000 variants) the build is about 3 s and the check about 3 s. ## Checked, nothing to fix

- Svelte and React divergence: pair DOM test over 126 states (gallery and themes), no difference.
- A11y: roles and ARIA of parts (`a11y` group, `KNOWN_ARIA`), one h1 per theme page (`requireH1`), skip link and focus to `main` (theme e2e), every id reference resolves, labels of tables, inputs and sortable headers.
- Dictionary: no Cyrillic in any source, doc, spec or key; every text of a view is a key.
- Drift: all generated files equal what the specs give; no manual edit in `apps/*` except `xgen.app.json`.

## Left, with reasons

1. Palette colors in `pill`, `rating`, `timeline` and text sizes in three canary parts (logo-sidebar, editor-tab, dropdown-item): they copy canary one-to-one; each is in the allow-list with its reason. Change them together with the canary recipes.
2. Lines of 450 to 600 characters in the authoring tables: under the limit; breaking them would make the tables unreadable.
3. ~~Links of the navigation bar~~ Done: the routes table of `xgen.app.json` drives the menu; the e2e clicks every link.
4. The site screen reads sources that block-level `data` could cover; harmless, not cleaned up.
5. ~~The dictionary check is prefix-based~~ Done: the `dictionary` group is leaf-exact; dynamic indexes (`status`, badges) are named.
6. No build cache for apps (see headroom above).
7. 142 of 325 variants appear only in the gallery, not in a theme page: this is by design (a page shows a good choice, the gallery shows all).
8. `bun run typecheck` of all apps takes about 2 min 15 s; a faster check would need project references.

## Typecheck of the apps (2026-10-05 follow-up)

`bun run typecheck` takes about 2 min 15 s. The time is the sum of independent `tsc`/`svelte-check` runs, one per package and per app (the script chains them with `&&`). The packages share no project references, so each run re-parses `@ui8kit/svelte-ui` / `@ui8kit/react-ui`. Speeding it up means either:
1. TypeScript project references (`composite: true`, one `tsc -b` at the root), or
2. Running the independent checks in parallel (a tool such as `bun run --parallel`).

`bun run typecheck` now runs the package and app checks in parallel (`bun run --filter … --parallel check`) after `typecheck:xgen`; wall time drops from about 2 min 15 s to the slowest single check (around 30–60 s). The generation layer itself is checked in under 2 s by `typecheck:xgen`. Leave the palette colors and canary text sizes alone (see "Left, with reasons" above).
