# Authoring specs for xgen: a practical guide

This guide is for someone new to the repo who has to add or change UI. In ui8kit you never write the
components themselves. You write **specs**, and `xgen` generates the same UI for eight runtimes:

| Runtime | Package | Host app |
|---|---|---|
| Svelte 5 | `packages/svelte/ui` | `apps/host-svelte` (port 5180) |
| React 19 | `packages/react/ui` | `apps/host-react` (5181) |
| Vue 3 | `packages/vue/ui` | `apps/host-vue` (5182) |
| Solid | `packages/solid/ui` | `apps/host-solid` (5183) |
| Go templ | `packages/templ/ui` | none (server templates) |
| Twig (PHP) | `packages/twig/ui` | none |
| Jinja2 (Python) | `packages/jinja2/ui` | none |
| Latte (PHP) | `packages/latte/ui` | none |

The four TypeScript runtimes have host apps that serve every screen. The four template runtimes (templ, Twig, Jinja2,
Latte) are checked by rendering every brick and block case with the real engine and comparing the DOM with React.

## 1. The golden rules

1. **Never edit a generated file.** Everything under `packages/*/ui`, `packages/shared/app` and `apps/host-*` starts with
   `Code generated by xgen. DO NOT EDIT.` and has a `Source:` line naming the spec it came from. `bun run check` (group
   `drift`) regenerates everything in memory and fails on any difference. Fix the spec, the builder or the emitter, then
   run `bun run build`.
2. **No literal text in views.** Every visible or announced word is a key in the dictionary `xgen/content/ui/en.json`
   (or a prop the organism receives).
3. **No Cyrillic** in any tracked file (group `text` scans `git ls-files`).
4. **Tags come from primitives only.** A view never names an HTML element directly (section 4).
5. **One `Block` per render path**, at the top of the file, with a semantic tag (section 4).
6. **Spacing on the 8 px grid**, 4 px steps only inside controls (section 8).

## 2. Where specs live

| What | Where | Written as | Generated into |
|---|---|---|---|
| Bricks (primitives) | `xgen/specs/ui/<name>.json` + `<name>.variants.json` | JSON by hand | `src/primitives/` (TS runtimes), `ui/` (template runtimes) |
| Parts (small pieces) | `xgen/specs/parts/*.json` | **TypeScript builder**: `xgen/screens/src/authoring/components/` | `src/components/` |
| Patterns (composite widgets) | `xgen/specs/patterns/*.json` | builder, same folder | `src/components/` |
| Organisms (page sections) | `xgen/specs/organisms/*.json` | builder: `xgen/screens/src/authoring/blocks/` | `src/blocks/` (`blocks/` in template runtimes) |
| Blocks (organism + axes + variants) | `xgen/specs/blocks/*.json` | builder: `xgen/screens/src/authoring/gallery/blocks*.ts` | gallery, catalog and theme screens |
| Recipes (variant tables of organisms) | `xgen/specs/recipes/*.variants.json` | JSON | next to the component |
| Presets (named layout classes) | `xgen/specs/presets/defaults.json` | builder: `authoring/presets/` | `src/presets/` |
| Screens | `xgen/specs/screens/*.json` | builder: `authoring/screens/`, `authoring/gallery/` | `apps/host-*/xgen/screens/` |
| Fixtures (sample data) | `xgen/fixtures/*.json` | JSON | `packages/shared/app` |
| Content (dictionary) | `xgen/content/ui/en.json` | JSON (+ tools) | `packages/shared/app` |

The tiers are: **bricks** (primitives, the only place that knows HTML tags) -> **parts / patterns** (components) ->
**organisms** (blocks). Organism ids say their tier: `organism.*`, `part.*`, `pattern.*`.

Important: the JSON in `specs/organisms`, `specs/parts`, `specs/patterns`, `specs/blocks`, `specs/presets` and
`specs/screens` is **written by `bun run build` from the TypeScript builder**. The `authored` group of `bun run check`
fails when the stored JSON differs from the builder. Edit the `.ts` file, not the JSON. Only bricks
(`specs/ui`), recipes, fixtures and content are edited as JSON.

## 3. Anatomy of the specs

### 3.1 A brick (`xgen/specs/ui/badge.json`, abridged)

```jsonc
{
  "$schema": "../../schema/schemas/spec.schema.json",
  "specVersion": 1,
  "id": "ui.badge",            // ui.<name>
  "tier": "brick",
  "dir": "badge",              // folder of the generated files
  "variants": { "badge": "badge.variants.json" },
  "parts": [{
    "name": "Badge",
    "recipeId": "badge",
    "classes": { "recipe": { "size": "Size", "variant": "Variant" } },   // recipe key -> prop
    "props": [
      { "name": "Variant", "type": "string", "cva": true, "docs": "color preset: default, secondary, destructive, outline" },
      { "name": "Size", "type": "string", "cva": true },
      { "name": "Class", "type": "string", "cva": false, "docs": "adds Tailwind utilities" },
      { "name": "Attrs", "type": "attrs", "cva": false },     // every other attribute, ARIA included
      { "name": "Children", "type": "children", "cva": false }
    ],
    "render": {                                             // the typed render tree
      "kind": "element", "tag": { "kind": "static", "tag": "div" },
      "attrs": [{ "kind": "class" }, { "kind": "static", "name": "data-slot", "value": "badge" }, { "kind": "rest" }],
      "children": [{ "kind": "slot" }]
    },
    "a11y": { "roots": ["div"], "roles": [], "aria": [], "keyboard": [] },
    "tokens": ["--border", "--primary"]
  }],
  "examples": [{ "id": "size.lg", "props": { "Size": "lg", "Variant": "default" } }]   // become parity cases
}
```

Brick props use PascalCase (`Variant`, `Size`, `Class`, `Attrs`). The `examples` become the brick cases that every runtime
must render identically.

### 3.2 Variants and sizes (`badge.variants.json`)

```json
{
  "id": "ui.badge",
  "base": "inline-flex shrink-0 items-center justify-center whitespace-nowrap font-medium inset-ring rounded-full",
  "keys": ["size", "variant"],
  "defaults": { "size": "default", "variant": "default" },
  "byKey": {
    "size": { "sm": "h-5 px-2 text-xs", "default": "h-6 px-3 text-xs", "lg": "h-8 px-4 text-sm" },
    "variant": { "default": "bg-primary text-primary-foreground inset-ring-primary", "secondary": "bg-muted text-foreground inset-ring-transparent" }
  },
  "compound": []
}
```

This is a CVA table: `base` + one class string per key value + optional `compound` rows. Controls share one size scale:
`sm / default / lg` = `h-8 / h-10 / h-12`. Organisms have their own tables in `xgen/specs/recipes/` and read them with
the `recipe` op (example from `pattern.file-tree-item`: `recipes: { fileTreeItem: "file-tree-item" }` and
`{ "op": "recipe", "args": ["fileTreeItem", "kind", { "$": "kind" }] }`).

### 3.3 An organism (builder: `xgen/screens/src/authoring/blocks/promo.ts`)

```ts
const announcementBar = spec("organism.announcement-bar", "AnnouncementBar", "A thin strip above the page ...", {
  props: [
    { name: "label", type: "string", required: true, docs: "accessible name of the strip" },
    { name: "text", type: "string", required: true },
    { name: "tone", type: tone, default: "default" },                    // a union type = a block axis
    { name: "layout", type: tsOf("center", "split"), default: "center" },
  ],
  view: [
    use("Block", { props: { Tag: "aside", Class: cn("w-full", cond(eq(ref("tone"), "muted"), "bg-muted text-foreground", "bg-primary text-primary-foreground")) },
                   attrs: { "aria-label": ref("label"), "data-testid": "announcement" } },
      use("Container", { props: { Class: "mx-auto w-full max-w-6xl px-4" } },
        use("Text", { props: { Size: "sm" } }, text(ref("text"))))),
  ],
});
```

Builder functions (`xgen/screens/src/build.ts`):

| Function | Meaning |
|---|---|
| `use(Name, { props, attrs }, ...children)` | a primitive (or part) |
| `text(value)` | a text node; the value is a prop, a dictionary key or an expression, never a literal word |
| `ref("x")` | the prop `x`; `ref("ui.some.key")` is a dictionary key |
| `when(test, then, else?)` | if / else |
| `each(items, "item", key, ...body)` | a loop |
| `slot(name, ...args)`, `organism(Name, props, { slots, on })` | slots and nested organisms |
| `cn`, `cond`, `eq`, `and`, `or`, `not`, `coalesce`, `len`, `money`, `preset`, ... | expressions (ops) |

Prop types: `"string"`, `"number"`, `"boolean"`, `{ ts: '"a" \| "b"' }` (`tsOf("a", "b")`), `{ record: "Name" }`
(a record declared in `records`). Organism props use camelCase JSON names; templates also accept `className`.

### 3.4 A block (builder: `xgen/screens/src/authoring/gallery/blocks-more.ts`)

```ts
const announcement = define({
  key: "announcement", theme: "promo", group: "banner", name: "Announcement bar", docs: "A thin strip above the page with one sentence and a link.",
  organism: "AnnouncementBar", axes: ["tone", "layout", "dismiss", "badge", "position"],   // props with a union type
  variants: [
    ["bar", "Primary strip"],                                         // [id, label, axis values?, case props?]
    ["muted", "Muted strip", { tone: "muted" }],
    ["shop", "Shop: free shipping, muted", { tone: "muted", dismiss: "show" }, annCase("shop")],
  ],
  sample: { label: t("promo.announcement.label"), text: t("promo.announcement.text"), ctaHref: "#/pricing" },
});
```

`t("promo.announcement.text")` is the dictionary key `ui.promo.announcement.text`. The allowed axis values and
defaults are read from the organism, so a block cannot disagree with it. Optional `facts` describe what each variant must
show in the browser (`{ sel: '[data-testid="item"]', n: 3 }`), and the e2e checks them.

## 4. Tags, primitives and Block

Composition (organisms, parts, patterns, screens) never writes an HTML tag. Pick the primitive and its `Tag`/`As` prop
(full rule: `.cursor/rules/01-block-root.mdc`):

| Primitive | Tags |
|---|---|
| `Block` | `div` (default), `section`, `article`, `aside`, `header`, `footer`, `main`, `nav`, `figure`, `search`, `hgroup` |
| `Box` | `div` only, never a wrapper or a root |
| `Container` | `div`, `main`, `section` |
| `Stack` | `div`, `ul`, `ol` |
| `Group` | `div`, `fieldset`, `dl` |
| `List` / `ListItem` | `ul`, `ol`, `dl`, `menu` / `li`, `dt`, `dd` |
| `Title` | `h1`..`h6` (`As` 1..6) |
| `Text` | `p` (default), `blockquote`, `figcaption`, `address`, `pre`, inline elements |
| `Inline` | `span` |

Plus `Button`, `Link`, `LinkPlain`, `Card*`, `Grid`, `Image`, `LucideIcon`, `Input`, `Select`, `Table*`, `Dialog` and the rest
of `xgen/specs/ui` (40 bricks, 72 parts). There are **no extra primitives** such as `Nav`, `Header`, `Article`: landmarks
and sectioning come only from `Block` with a semantic `Tag`. Do not add a primitive for one use.

Block rules (detector `block-root` of `bun run rules`):

- An organism (blocks) opens on `Block` with a semantic tag (`section`, `aside`, `header`, ...).
- At most **one `Block` per render path**. Mutually exclusive branches of `when(...)` may each have their own Block.
- Never a `Block` nested in another `Block` of the same component, never in an `each` loop. Need one there? Make it a
  separate part (for example `NavBlock`, `FigureBlock`, `ArticleBlock` in `authoring/components/landmarks.ts`).

## 5. Text, the dictionary and landmark labels

- Texts live in `xgen/content/ui/en.json`. A view reads them by key (`ref("ui.promo.announcement.text")`, or `t(...)`
  in block files). The `dictionary` group fails when a key is read but missing, or exists but nobody reads it.
- The names, notes and variant labels of blocks are copied into the dictionary by a tool. Run it after adding or
  renaming a block or variant: `bun xgen/screens/tools/author-block-texts.ts`.
- **Landmark labels.** Every organism whose view holds a landmark automatically gets an optional prop `landmarkLabel`
  (`authoring/landmarks.ts`). It replaces the root landmark's accessible name, so a page that shows the same block twice
  still has distinct landmarks. Give your root landmark a name anyway: `attrs: { "aria-label": ref("title") }` or
  `aria-labelledby` pointing at the heading.

## 6. ARIA

ARIA goes through `attrs` (`Attrs` on bricks); there are no role props. Prefer static ARIA (`"aria-hidden": "true"`,
`role: "group"`) or a name from a prop. A reactive ARIA state (`aria-expanded` computed from state) is reported by the
`reactive-aria` detector; existing cases are recorded in `rules/baselines/*.json`, new ones fail.

## 7. Presets

`xgen/specs/presets/defaults.json` holds named class sets for the geometry of blocks (`hero.band`, `text.tiny`, ...).
Read them with `preset("defaults", "hero.band")` in the builder. Swapping the preset resizes every block that uses it.

## 8. Spacing and style policy

- **8 + 4:** layout spacing (`gap`, `p*`, `m*`, `space-*`, `inset`, sizes) uses even Tailwind steps (8 px grid: `gap-2`,
  `p-4`, `py-16`). Odd steps (4 px: `gap-1`, `px-3`) are allowed only inside controls (the `controls` scope in
  `.ui8px/policy/scopes.json`). Hairlines `gap-px`/`p-px` are allowed.
- `bun run lint:px` extracts every class set of the specs and fails on any blocking hit (`UI8PX001`, `UI8PX003`,
  `UI8PX005`, `GRID`). The ratchet in `.ui8px/gate.json` is `max: 0`. `UI8PX002` and `UI8PX004` are report-only.
- `bun run check` adds: one corner token (plain `rounded`), shadows only on floating layers, no arbitrary values or
  palette colors (`hardcode`), Tailwind-step spacing keys (`spacing`), size limits (`readability`).

## 9. Commands

```sh
bun run build                 # specs -> all 8 runtimes, shared app, host apps (also rewrites authored JSON)
bun run check                 # every gate; includes drift, rules, and real-engine parity for templ/solid/twig/jinja2/latte
bun run test                  # bun test of xgen/*
bun run lint:px               # spacing gate
bun run rules:baseline        # rewrite rules/zones.json and rules/baselines after an accepted change
bun run build:hosts           # vite build of the 4 host apps (needed before e2e)
XGEN_E2E_ONLY=blocks,theme-promo-campaign bun run e2e   # browser e2e of some screens; without the variable: all
bun run check:all             # everything above in order
```

The template runtimes need their toolchains: Go for templ, PHP 8.2+ with composer for Twig and Latte, Python 3 for Jinja2.
Without them the group prints `skipped: ...` locally. With `UI8KIT_REQUIRE_ALL_RUNTIMES=1` (CI) a skip is a failure.
The pre-push hook (`bun run hooks:install`) runs `bun run check` and the audit. Never bypass it.

## 10. Reading `bun run check` output

Each group prints `ok` or `FAIL` and then one line per problem, with the file and what to do:

```
FAIL  themes   every theme is a screen spec, every block is used by a theme, ...
        block keyfigure: not used by any theme screen; add it to a page in screens/src/authoring/screens/themes.ts
```

Common failures:

| Message | Fix |
|---|---|
| `drift: ... differs from the generated file (run: bun run build)` | run `bun run build`; if it persists, someone edited a generated file: revert it |
| `authored: ... differs` | you edited JSON in `specs/organisms` etc. Edit the builder `.ts` instead and build |
| `CatalogScreen: <block>.<variant> is in no category` | add the block to a category in `authoring/gallery/catalog.ts` |
| `block <key>: not used by any theme screen` | add a variant to a page in `authoring/screens/themes.ts` |
| `dead: <block>.json: no facts and no branch in ... e2e` | add `facts` to the block, or a case in `xgen/check/src/e2e/generic.ts` |
| `dictionary: key ... missing` / `not read` | add or remove the key in `en.json`; rerun `author-block-texts.ts` for block labels |
| `rules/zones.json: differs ...; run: bun run rules:baseline` | a new generated file joined a zone: run it and commit the result |
| `rules: <file>:<line> block-root ...` | a second/nested Block, or a root that is not Block: restructure or extract a part |
| `twig/jinja2/latte/templ: <case>: DOM differs` with a `react:` / `<runtime>:` pair | an emitter bug or an op the runtime lacks; compare the two lines |
| `xgen build: N problem(s) in the inputs, nothing written` | the build refused invalid specs; the lines above say which |

## 11. Walkthrough: a new organism end to end

This was done in a scratch branch on 2026-10-13 and passed `bun run check`, `bun run lint:px` and
`XGEN_E2E_ONLY=theme-promo-campaign bun run e2e`. The example adds `KeyFigure`, a section showing one big number.

**Step 1. Write the organism** in a new file `xgen/screens/src/authoring/blocks/key-figure.ts`:

```ts
import { cn, cond, eq, ref, text, use, when } from "../../build";
import type { OrganismSpec } from "../../ir";
import { spec } from "../kit";
import { tsOf } from "../props";

const keyFigure = spec("organism.key-figure", "KeyFigure", "One big number with a caption and a short note. Axes: tone (default, muted), align (start, center).", {
  props: [
    { name: "title", type: "string", required: true, docs: "heading of the section" },
    { name: "value", type: "string", required: true, docs: "the figure, already formatted" },
    { name: "caption", type: "string", required: true },
    { name: "note", type: "string" },
    { name: "tone", type: tsOf("default", "muted"), default: "default" },
    { name: "align", type: tsOf("start", "center"), default: "start" },
  ],
  view: [
    use("Block", { props: { Tag: "section", Class: cn("w-full py-16", cond(eq(ref("tone"), "muted"), "bg-muted", "")) }, attrs: { "aria-label": ref("title"), "data-testid": "key-figure" } },
      use("Container", { props: { Class: "mx-auto w-full max-w-6xl px-4" } },
        use("Stack", { props: { Gap: "2", Class: cond(eq(ref("align"), "center"), "items-center text-center", "items-start") } },
          use("Title", { props: { As: 2, Size: "lg" } }, text(ref("title"))),
          use("Text", { props: { Size: "5xl", Weight: "bold" }, attrs: { "data-testid": "key-figure-value" } }, text(ref("value"))),
          use("Text", { props: { Size: "sm", Class: "text-muted-foreground" } }, text(ref("caption"))),
          when(ref("note"), [use("Text", { props: { Size: "xs", Class: "text-muted-foreground" } }, text(ref("note")))])))),
  ],
});

export const keyFigureOrganisms: OrganismSpec[] = [keyFigure];
```

**Step 2. Register it** in `authoring/blocks/organisms.ts`: import `keyFigureOrganisms` and add `...keyFigureOrganisms`
to `allOrganisms`.

**Step 3. Define the block** in `authoring/gallery/blocks-more.ts` (and add `keyFigure` to `moreBlocks` at the bottom):

```ts
const keyFigure = define({
  key: "keyfigure", theme: "promo", group: "banner", name: "Key figure", docs: "One big number with a caption.",
  organism: "KeyFigure", axes: ["tone", "align"],
  variants: [["start", "Number on the left"], ["center", "Centered, muted", { align: "center", tone: "muted" }]],
  facts: [{ sel: '[data-testid="key-figure-value"]', n: 1 }],
  sample: { title: t("promo.keyfigure.title"), value: "98%", caption: t("promo.keyfigure.caption"), note: t("promo.keyfigure.note") },
});
```

**Step 4. Add the texts** to `xgen/content/ui/en.json` under `promo`:

```json
"keyfigure": { "title": "Customer satisfaction", "caption": "of customers would recommend us", "note": "Survey of 1200 customers, 2026." }
```

then copy the block name and variant labels into the dictionary: `bun xgen/screens/tools/author-block-texts.ts`.

**Step 5. Build and read the check.** `bun run build` refuses at first:
`CatalogScreen: keyfigure.start is in no category`. `bun run check` also reports the theme and `dead` problems from the
table in section 10. Fix them:

- `authoring/gallery/catalog.ts`: `...all("announcement", "cookie", "keyfigure")` in the `promo-banners` category;
- `authoring/screens/themes.ts`: add `"keyfigure.start"` and `"keyfigure.center"` to pages of the promo theme;
- the `facts` in step 3 cover the `dead` group (or add a case in `xgen/check/src/e2e/generic.ts`).

**Step 6. Build again, then refresh the zones**: `bun run build`, then `bun run rules:baseline` (the new
`blocks/key-figure.*` files join the block-root zone in `rules/zones.json`).

**Step 7. Verify**: `bun run check` (all groups ok, including real Twig/Jinja2/Latte/templ parity of the new block
cases), `bun run test`, `bun run lint:px`, then `bun run build:hosts` and
`XGEN_E2E_ONLY=blocks,theme-promo-campaign bun run e2e`.

**Step 8. Commit** the builder files, `en.json`, the generated JSON specs (`specs/organisms/key-figure.json`,
`specs/blocks/keyfigure.json`, the changed screens), all generated packages and apps, and `rules/zones.json`. Push
through the normal hook.
